1. Ringkasan Project

Sistem ini adalah aplikasi web untuk menampilkan informasi kas cluster secara transparan kepada warga, sekaligus membantu bendahara mengelola:

  • saldo kas,
  • status pembayaran iuran bulanan,
  • upload bukti transfer warga,
  • verifikasi pembayaran,
  • pencatatan pengeluaran,
  • laporan keuangan,
  • audit log aktivitas penting.

Sistem memiliki 2 jenis pengguna utama: Bendahara (Admin) dan Warga (Akun Rumah).

2. Tujuan Project

  1. Memudahkan bendahara melaporkan kondisi kas cluster.
  2. Memberikan transparansi saldo dan arus kas kepada warga.
  3. Mengurangi pertanyaan berulang ke bendahara.
  4. Mencatat rumah yang sudah/belum membayar iuran.
  5. Menyediakan bukti pembayaran dan verifikasi yang rapi.
  6. Menyediakan laporan pemasukan dan pengeluaran.
  7. Meningkatkan akuntabilitas melalui audit log.

5. Asumsi Bisnis

  1. Sistem berbentuk web app full-stack, deploy ke Cloudflare.
  2. Database Cloudflare D1, file bukti di Cloudflare R2.
  3. Satu rumah satu akun.
  4. Iuran bulanan, nominal sama untuk semua rumah, tanpa denda.
  5. Pembayaran boleh rapel.
  6. Bukti transfer wajib diupload warga; sah setelah diverifikasi bendahara.
  7. Bendahara dapat menyetujui atau menolak bukti.
  8. Bukti transfer hanya dapat dilihat bendahara dan pemilik akun pengunggah.
  9. Bukti pengeluaran opsional dan default hanya untuk bendahara.
  10. Nama pemilik tidak ditampilkan ke warga.
  11. Papan publik menampilkan nomor rumah + status tanpa nama pemilik.
  12. Password default wajib diganti saat login pertama.
  13. Rumah kosong / tanah kosong dapat ditandai aktif / nonaktif.
  14. Audit log diperlukan untuk aktivitas penting.

8. Aturan Bisnis

8.1 Status Pembayaran

StatusKondisi
Belum BayarTidak ada pembayaran verified dan tidak ada pending.
Menunggu VerifikasiAda bukti terupload, belum diverifikasi bendahara.
Sudah BayarAda pembayaran verified tetapi belum sampai bulan berjalan.
LunasPembayaran verified sudah mencakup bulan berjalan atau lebih.

8.2 Prioritas Status

Jika ada pembayaran pending, status utama = Menunggu Verifikasi, namun sistem tetap menampilkan “sudah bayar sampai bulan X” dan “menunggu verifikasi untuk bulan Y”.

8.3 Perhitungan Saldo

Saldo = saldo_awal + total pemasukan verified - total pengeluaran

- Pending payment TIDAK menambah saldo.
- Rejected payment TIDAK menambah saldo.

8.4 Format & Zona Waktu

  • Zona waktu: Asia/Jakarta (bulan berjalan mengikuti WIB).
  • Format bulan: YYYY-MM (contoh 2026-07).
  • Nominal uang disimpan sebagai integer rupiah (contoh 50000), bukan float.

10. Acceptance Criteria

SkenarioKriteria
Login wargaUsername+password benar → masuk dashboard warga. Jika password default → diarahkan ganti password.
Upload buktiPilih bulan + upload bukti → status Menunggu Verifikasi; saldo belum bertambah.
ApproveKlik “Sudah Bayar” → payment verified, paid_until bertambah, ledger income dibuat, saldo bertambah, audit log tercatat.
RejectTolak + alasan → payment rejected, bulan kembali belum dibayar, warga bisa upload ulang.

15. Logika Status Pembayaran

current_month   = bulan sekarang (YYYY-MM, zona Asia/Jakarta)
required_months = billing_start_month .. current_month
paid_months     = payment_items.status = 'paid'
pending_months  = payment_items.status = 'pending'

if pending_months tidak kosong:
    status = "Menunggu Verifikasi"
else:
    unpaid = required_months - paid_months
    if unpaid kosong:            status = "Lunas"
    else if paid_months ada:     status = "Sudah Bayar"
    else:                        status = "Belum Bayar"

Contoh

Kondisi (bulan berjalan 2026-07)StatusKeterangan
Paid 01–04, pending kosongSudah BayarSampai Apr 2026; belum bayar Mei–Jul
Paid 01–07, pending kosongLunasLunas sampai Jul 2026
Paid 01–04, pending 05–06Menunggu VerifikasiSudah bayar s/d Apr; menunggu Mei–Jun; belum bayar Jul
Paid kosong, pending kosongBelum BayarBelum bayar Jan–Jul

16. Transaksi Verifikasi & Reject

16.1 Saat bendahara klik “Sudah Bayar”

1. UPDATE payments SET status='verified', verified_at=now, verified_by=admin_id
2. UPDATE payment_items SET status='paid' WHERE payment_id=?
3. Hitung ulang houses.paid_until (bulan paid berurutan terlama)
4. UPDATE houses SET paid_until=?
5. INSERT ledger_entries (entry_type='income', amount, payment_id, house_id)
6. INSERT audit_logs (action='approve_payment')

16.2 Saat bendahara menolak

1. UPDATE payments SET status='rejected', rejected_reason=?
2. UPDATE payment_items SET status='rejected' WHERE payment_id=?
3. houses.paid_until TIDAK berubah
4. INSERT audit_logs (action='reject_payment')

23. Flow Utama Sistem

23.1 Warga upload bukti

Login → (wajib ganti password jika default) → dashboard warga
→ klik Upload Bukti → pilih bulan (mulai tunggakan terlama, berurutan)
→ sistem hitung total → upload file → submit
→ status Menunggu Verifikasi → bendahara memeriksa
→ valid: Sudah Bayar | tidak valid: Tolak (+alasan, warga upload ulang)

23.2 Bendahara verifikasi

Login admin → dashboard → menu Menunggu Verifikasi → pilih payment
→ lihat bukti → cek nominal & bulan
→ [Sudah Bayar]: payment verified, items paid, paid_until update, ledger income, audit
→ [Tolak]: payment rejected + alasan, items rejected, audit

23.3 Bendahara mencatat pengeluaran

Login admin → Pengeluaran → Tambah → isi tanggal/nominal/keterangan (+bukti opsional)
→ simpan → ledger expense dibuat → saldo berkurang → tampil di laporan → audit
