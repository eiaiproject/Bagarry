# Audit antislop 001, 14 September 2026

Mode 2 (setelah selesai). Objek audit: aplikasi Kas Amartha Cluster Bagarry
(`src/`, `README.md`). Cara audit: pembacaan kode dan HTML hasil render, pengukuran
kontras dengan perhitungan WCAG, dan menjalankan aplikasi di lokal.

Prioritas mengikuti tingkat aturan: Hard Gate = TINGGI, Purpose-Gate = SEDANG,
Quality Locks = RENDAH.

Tidak ada berkas yang diubah sebelum nomor temuan disetujui.

---

## Daftar temuan

### 01. TINGGI, R-25, dua pasangan warna di bawah WCAG AA 4,5:1

Dua tempat gagal, keduanya pada latar `#f1f5f9` dengan teks `#64748b`:

| Tempat | Rasio | Batas |
| --- | --- | --- |
| `.input:disabled` di `src/lib/layout.ts:50` (teks `#64748b` di latar `#f1f5f9`) | 4,34:1 | 4,5:1 |
| `footer.site` di `src/lib/layout.ts:190` (teks `#64748b` di latar `#f1f5f9`) | 4,34:1 | 4,5:1 |

Seluruh 28 pasangan warna lain yang dipakai lulus, termasuk empat warna badge status,
`.stat-focus` (`#ccfbf1` di `#0f766e`, 4,86:1), `#cbd5e1` di header gelap (12,02:1),
dan cincin fokus `#0d9488` (3,42 sampai 4,77:1, batas 3:1 untuk komponen non-teks).

Perbaikan: ganti `#64748b` menjadi `#475569` pada dua tempat itu (7,58:1 dan 7,24:1).

### 02. TINGGI, R-27, tidak ada loading state

Empty state dan error state ada: `emptyState()` di `src/lib/html.ts:38`, tabel kosong
memakai pesan yang sama (`src/lib/html.ts:51`), halaman galat di `src/routes/shared.ts:27`
dan `src/index.ts` (`notFound` dan `onError`). Loading state tidak ada.

Alasan: aplikasi dirender di server dan tidak memakai `fetch()` di klien (tidak ada satu
pun pemanggilan `fetch(` di `src/`), jadi perpindahan halaman ditangani browser. Tetapi
setiap form `POST` (verifikasi, tolak, simpan pengaturan, catat pengeluaran, unggah bukti)
tidak memberi umpan balik saat sedang diproses, sehingga pengguna di koneksi lambat bisa
menekan tombol dua kali.

Perbaikan: matikan tombol submit dan ubah labelnya saat form dikirim, memakai satu
`<script>` kecil di `renderPage`.

### 03. TINGGI, R-35, belum ada click-through di peramban

Mesin ini tidak punya Chrome, jadi aturan "klik setiap elemen interaktif dan catat
hasilnya" tidak bisa dijalankan. Yang tersedia sebagai bukti:

- `npx tsc --noEmit` bersih, `npx vitest run` 22/22 lulus.
- `bash scripts/smoke.sh` terhadap `wrangler dev` lokal: 96 pemeriksaan lulus, 0 gagal
  (migrasi + `seed/example-houses.sql` + `seed/example-accounts.sql`). Cakupannya
  termasuk login, ganti password wajib, rate limit, pengaturan, kelola rumah, import CSV,
  unggah bukti, verifikasi, penolakan, pengeluaran, laporan, batas akses antar berkas,
  dan render seluruh halaman.
- Semua 14 tautan navigasi punya rute yang benar-benar terdaftar.
- Semua `href` berupa path nyata, tidak ada `href="#"`, `href=""`, atau `href="javascript:"`.

Perbaikan: jalankan aplikasi dan klik setiap elemen di peramban, lalu catat hasilnya
sebagai bukti seperti yang diminta R-35.

### 04. SEDANG, R-38 dan C-5, README menyebut teknologi yang tidak dipakai

`README.md` bagian Teknologi menulis "Tampilan: HTML dirender server + Tailwind Play CDN,
tanpa proses build". Tidak ada Tailwind di mana pun: tidak ada di `src/`, tidak ada di
`package.json`, tidak ada di `wrangler.jsonc`. Seluruh gaya ditulis tangan di konstanta
`STYLES` pada `src/lib/layout.ts`. Dokumen yang menyebut teknologi yang tidak dipakai
adalah klaim yang tidak berdasar.

Perbaikan: hapus bagian "+ Tailwind Play CDN" dari baris itu.

### 05. RENDAH, R-21, tema terang tetap tanpa alasan tertulis

Aplikasi hanya punya satu tema terang, tanpa sakelar tema dan tanpa `prefers-color-scheme`.
Alasan "papan informasi publik dibaca warga dari HP pada siang hari" bisa diterima, tetapi
alasan itu belum tertulis di bagian Arah desain README, sedangkan R-31 mewajibkan setiap
keputusan besar punya alasan tertulis.

Perbaikan: tambahkan satu baris alasan di README, atau pasang sakelar terang/gelap.

### 06. TINGGI, R-35, jalur verifikasi di README rusak setelah seed contoh

Bukan pelanggaran gaya, tetapi cacat bukti verifikasi. `package.json` sudah memisahkan
seed: `db:seed:local` hanya memuat rumah dan akun contoh, sedangkan `db:seed:demo:local`
menambahkan `seed/example-payments.sql`. Yang bermasalah adalah smoke sendiri: ia menguji
angka absolut sehingga keadaan data sebelum menjalankannya mengubah hasilnya. Setelah
data aktivitas kas contoh dimuat (`db:seed:demo:local`), `npm run smoke` gagal 6
pemeriksaan:

```
FAIL  Saldo awal kas terbaca di papan publik (harap 1000000, dapat 850000)
FAIL  Unggahan gagal tidak membuat pengajuan
FAIL  Pengajuan masuk daftar menunggu verifikasi
FAIL  Pengeluaran masuk bulan berjalan
FAIL  Laporan mencatat pemasukan 100000
FAIL  Laporan mencatat pengeluaran 350000
```

Hasil di tiga kondisi berbeda:

| Kondisi awal | Hasil smoke |
| --- | --- |
| hanya migrasi | 95 lulus, 1 gagal (`Jumlah rumah contoh terbaca`, `.counts.active >= 5`) |
| migrasi + rumah + akun contoh (`db:seed:local`) | 96 lulus, 0 gagal |
| migrasi + rumah + akun + aktivitas kas contoh (`db:seed:demo:local`) | 90 lulus, 6 gagal |

Jadi smoke bergantung pada data contoh rumah dan akun, tetapi rusak oleh data contoh
pembayaran dan pengeluaran.

Perbaikan: pisahkan seed demo (rumah + akun + aktivitas kas) dari seed yang dibutuhkan
smoke, dan ubah assertion smoke menjadi relatif (baca nilai awal, bandingkan selisihnya)
supaya tahan terhadap data yang sudah ada.
