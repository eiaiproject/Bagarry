# Audit antislop 003, 14 September 2026: pixel-perfect dan UX desktop + mobile

Mode 2 (setelah selesai). Objek: seluruh tampilan web aplikasi Kas Amartha
Cluster Bagarry (17 rute HTML: `/`, `/login`, `/ganti-password`, 4 warga, 11
admin). Cara audit: Chromium headless nyata di atas server audit port 8791
(data pasca-e2e: 10 rumah, 11 user), viewport desktop 1280x900, mobile 360x740
(pola Android) dan 390x844 (pola iOS), ditambah baca DOM via curl dan ukur
kontras via `skills/antislop-human/contrast-check.py`.

Prioritas: Hard Gate = TINGGI, Purpose-Gate = SEDANG, Quality Locks = RENDAH.
Nomor temuan melanjutkan audit-002 (berikutnya 09). Tidak ada berkas `src/`
yang diubah sebelum nomor disetujui.

---

## Daftar temuan

### 09. TINGGI, R-03, nav admin meluap di desktop 1280px

`.nav-inner` admin berisi 9 item (total ±1200px: Dashboard 122, Menunggu
Verifikasi 179, Kelola Rumah 135, Pembayaran 128, Pengeluaran 128, Laporan 101,
Pengaturan 122, Audit Log 109, Ganti Password 148). Di viewport 1280px sisa
ruang setelah padding ±125px terpakai, sehingga `navScroll = 125px`: item
terakhir ("Ganti Password") terpotong dan hanya terlihat lewat geser
horizontal. Diukur di browser nyata, bukan tebakan. Warga (5 item,
navScroll 303-333px di 360px) memang dirancang geser, tetapi nav admin
seharusnya muat penuh di desktop karena penggunanya bekerja di layar lebar.

Alasan satu baris: 9 item selebar ±1200px tidak muat di konten 1048px.

Perbaikan: di desktop, kecilkan padding/gap `.nav-link` dan izinkan label
2 baris atau pindahkan "Ganti Password" ke menu header (dekat tombol Keluar),
sehingga 8 item muat tanpa geser di 1280px. Ukuran sentuh 44px tetap dijaga
di mobile (aturan geser yang ada dipertahankan di bawah breakpoint).

### 10. TINGGI, R-03, header brand 2 baris di 360px menekan konten

Di 360px judul header "Kas Amartha Cluster Bagarry" pecah menjadi 2 baris
(terlihat di screenshot `Tambah rumah` dan `Upload bukti transfer` mobile:
"NAMA APLIKASI" menumpuk, tinggi header 2x). Ditambah nav geser 845px di bawahnya,
chrome atas memakan ±150px sebelum konten dimulai. Di 390px (iOS) masalah sama,
hanya sedikit lebih lega.

Alasan satu baris: brand 27 karakter + label peran + tombol Keluar tidak muat
sebaris di 328px konten.

Perbaikan: di bawah ±480px, singkat brand menjadi "Bagarry" atau "Kas Bagarry"
(1 baris), pertahankan nama lengkap di `title` dan desktop. Alternatif: kecilkan
font brand ke 13px dan sembunyikan label peran (`.who`) di layar sempit.

### 11. SEDANG, R-05, 9 link nav admin tanpa hierarki visual

Semua item nav admin setara: Dashboard, Menunggu Verifikasi, Kelola Rumah,
Pembayaran, Pengeluaran, Laporan, Pengaturan, Audit Log, Ganti Password.
Tugas utama bendahara ("ada yang menunggu verifikasi?") tidak menonjol;
"Menunggu Verifikasi" terlihat sama dengan "Audit Log". Diukur: 9 link,
navScroll 845px di 360px, tidak ada badge hitung pending.

Alasan satu baris: frekuensi pakai (harian vs bulanan) tidak tercermin di nav.

Perbaikan: tambahkan hitung pending di label nav ("Menunggu Verifikasi (n)")
atau pisahkan grup: operasional (Dashboard, Menunggu, Pembayaran, Pengeluaran)
vs administrasi (Rumah, Laporan, Pengaturan, Audit). RHYTHM 1 tetap: yang
berubah hanya label/pengelompokan, bukan dekorasi.

### 12. SEDANG, input 14px memicu auto-zoom iOS Safari

Semua `.input` memakai `font-size:14px` (terukur di settings, reports, houses/new,
pembayaran). iOS Safari memperbesar otomatis (auto-zoom) setiap input dengan
font di bawah 16px saat fokus, menggeser layout dan membingungkan warga yang
mayoritas membuka dari HP. Tidak ada `maximum-scale=1` (bagus, jangan
ditambahkan karena merusak aksesibilitas), jadi satu-satunya perbaikan benar
adalah menaikkan font input.

Alasan satu baris: 14px < ambang 16px auto-zoom Safari.

Perbaikan: naikkan `.input` ke `font-size:16px` (tinggi 44px tetap, lebar tidak
berubah karena `width:100%`). Label 12px dan hint 12-13px boleh tetap karena
bukan kolom ketik.

### 13. RENDAH, R-31, tombol tabel 38px di desktop tanpa alasan tertulis

`.btn-sm` 38px di desktop, naik ke 44px di bawah 640px (media query). Keputusan
ini benar secara ergonomi (mouse presisi vs jempol), tetapi alasannya hanya ada
di komentar kode, tidak di README bagian Arah desain. R-31 mewajibkan alasan
tertulis untuk keputusan besar.

Alasan satu baris: dokumentasi kurang satu baris.

Perbaikan: tambah satu baris di README Arah desain ("Tombol tabel 38px di
desktop, 44px di mobile karena presisi mouse vs jempol").

### 14. RENDAH, tabel audit 6 kolom di mobile hanya bisa digeser

`/admin/audit` (Waktu, Aktor, Aksi, Entity, Perubahan, IP) dan tabel tunggakan
dashboard terukur `LEAK` di 360px: tertampung benar di `.table-wrap` scroll
(tidak ada overflow halaman, `leak:0` di semua halaman), tetapi di HP bendahara
harus geser horizontal untuk membaca kolom Perubahan/IP. Kolom Perubahan berisi
JSON mentah (`old_values`/`new_values`) yang panjang.

Alasan satu baris: 6 kolom + JSON mentah memang tidak muat di 328px.

Perbaikan (pilih satu): (a) biarkan geser, anggap cukup karena audit dipakai
sesekali dari desktop; (b) ringkas kolom Perubahan menjadi ringkasan
("saldo 1jt menjadi 750rb") dan sembunyikan kolom IP di bawah breakpoint.
Opsi (a) nol kode; opsi (b) butuh format ulang satu sel.

## Yang diperiksa dan lulus

| Area | Bukti |
| --- | --- |
| Overflow halaman | `leak:0` di 24 kombinasi halaman x viewport (1280, 360, 390). Tabel `LEAK` selalu di dalam `.table-wrap` scroll, bukan halaman. |
| Target sentuh mobile | `smallCount:0` di semua halaman 360/390px: tombol 44px, `.month-row`/`.check-row` 44px, `.btn-sm` naik ke 44px. Di desktop `.btn-sm` 38px + tombol Keluar 38px: benar untuk mouse, dilindungi pengecualian WCAG 2.5.8 untuk kontrol yang punya padanan mobile. |
| Nav warga mobile | 5 item, geser horizontal 303-334px, item tidak terjepit; pola sesuai skill mobile (scrollable row, bukan hamburger palsu). |
| Tidak ada fixed/sticky | `position:fixed/sticky` 0, `100vh` 0: tidak ada header menutupi konten, tidak ada slab viewport di HP. Safe-area tidak relevan karena tidak ada bar bawah fixed. |
| Form Android | Semua input berlabel (`label for` atau wrapping label), `h=44px`, `required` tepat, `accept` file benar (jpg/png/pdf), fieldset+legend di pilihan bulan, JS menegakkan urutan bulan + total rupiah live. |
| Fokus keyboard | `:focus-visible` 3px `#0d9488` terukur dari gaya terhitung, Tab order = urutan visual (brand, Keluar, nav berurutan), `aria-current="page"` di menu aktif. |
| Zoom 200% | `body zoom 200%`: `leak:0`, layout menampung. |
| Kontras | 17 pasangan diukur via script: semua teks lulus (badge 6,15-8,30:1; hint `#475569` 6,92:1 di halaman + 7,58:1 di putih pasca temuan 07; brand `#5eead4` 12,07:1; `.who` `#cbd5e1` 12,02:1). Ikon nav `#64748b` 4,76:1 di atas putih: non-teks berlabel (batas 3:1) jadi lulus. |
| Kontrol mati | `href="#"`/`href=""`/`javascript:` 0 di semua halaman; setiap `<button>` di dalam `<form>` nyata; 404 benar untuk halaman tidak dikenal. |
| Konsistensi | Radius 8/10/999, tanpa shadow/glow/animasi (MOTION 1), badge hanya status nyata, font sistem, satu tema terang beralasan. |
| Copy | Tanpa CTA generik, buzzword, em dash, testimoni, statistik palsu, atau FAQ template. |

## Batas audit ini

- Pengujian memakai Chromium headless (Android UA tidak mengubah perilaku karena
  tidak ada kode khusus UA; iOS Safari asli tidak tersedia di mesin ini, jadi
  temuan 12 didasarkan pada ambang 16px yang terdokumentasi, bukan rekaman
  perangkat).
- Glif ikon tetap belum dinilai mata manusia (bawaan dari tindak lanjut 001).
- Perilaku keyboard fisik HP (menutupi input) belum diuji di perangkat nyata.
